The Anatomy of a Web Application

How modern software systems work, translated into medical residency advising.

When approaching software with no technical background, code can feel like an impenetrable wall of syntax. But building software is fundamentally about architecture and workflow, not memorizing code keywords.

Every web application—including the residency advising portal you are setting out to build—operates across three cooperating layers.

The Three Core Layers

1. Client / Frontend

The User Interface

Everything the medical student or faculty advisor sees and interacts with in Google Chrome or Safari: text boxes, character counters, buttons, and radar graphs.

Analogy: The Clinic Exam Room where the patient and doctor talk face-to-face.
2. Server / Backend

The Logic & Rules Engine

The invisible decision-maker. It enforces official AAMC rules (e.g. strict 750-character caps), calculates competitiveness scores, and communicates with AI models.

Analogy: The Clinical Diagnostic Protocol that evaluates lab values against medical guidelines.
3. Database / Storage

The Permanent Vault

Where information is permanently stored in organized tables: student rosters, drafted essays, advisor feedback notes, and 5,500+ ACGME residency programs.

Analogy: The Electronic Health Record (EHR) where historical patient charts are safely kept.

A Concrete ERAS Advising Example

Imagine a student named Sarah is preparing her application for an Internal Medicine residency. Here is what happens under the hood during a single advising interaction:

  1. Sarah types in the Frontend: She enters her clinical volunteering experience. The frontend immediately updates a live character counter: 682 / 750 characters.
  2. Sarah clicks "Submit for Advisor Review": The frontend sends the draft across the internet to the Backend.
  3. The Backend validates and processes: The backend verifies that Sarah has not exceeded the 10-experience limit and notifies her assigned advisor, Dr. Martinez.
  4. The Database stores the record: The database safely saves the timestamp, Sarah's draft, and updates the status to "In Review". Even if Sarah shuts her laptop, her work is completely secure.
Your Role as the Product Lead

Because you are directing AI to build this application, you do not need to memorize how to write database queries or styling syntax. Your job is to define the rules of the clinic: What are the character limits? Who is allowed to review a draft? What data should an advisor see before signing off?

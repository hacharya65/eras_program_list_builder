Quick Reference Guide #01

The 3-Layer Web App Architecture

A cheat sheet mapping standard software layers to the Medical Residency Advising domain.

Architectural Matrix

Layer What It Does ERAS Advising Example Tools We Use
Frontend (Client) Renders user interfaces in the browser, registers clicks and text input, counts characters in real time. The student typing their 750-character clinical description; selecting Gold/Silver program signals. React, Next.js, HTML/CSS
Backend (Server / API) Enforces business rules, runs algorithms, authenticates users, talks to AI services. Calculates the Specialty Competitiveness Index ($SCI$); calls Gemini for Socratic drafting prompts. Next.js Route Handlers, Node.js
Database (Storage) Persistently stores, indexes, and secures structured records in tables with access controls. Tables for students, advisors, experiences, acgme_programs, and nrmp_benchmarks. PostgreSQL (Supabase)

Hospital / Clinical Analogy

The Clinical Metaphor

The Exam Room / Triage Desk (Frontend): Where the patient meets the clinical staff, answers questions, and sees their vitals on a monitor.

The Clinical Protocol / Treatment Algorithm (Backend): The diagnostic logic that interprets the vitals, flags contraindications, and orders the proper labs.

The Electronic Health Record (EHR / Database): The permanent, HIPAA-compliant vault where patient encounters, history, and lab results are securely saved and fetched.

Golden Rules for the Non-Technical Creator

  1. Never store data on the frontend: If a student refreshes their browser, any data not sent to the database is lost.
  2. Enforce critical limits on the backend: Even if the frontend has a character counter, the backend must guarantee that no text over the AAMC limit is accepted.
  3. Respect user roles: Students only edit their own draft; advisors can read their advisees' drafts and leave feedback; deans see aggregate cohort stats.

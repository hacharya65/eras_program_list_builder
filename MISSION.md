# Mission: Building an ERAS Residency Advising Web Application

## Why
Eliminate the chaotic cycle of emailing multiple Google Doc versions back and forth to advisors with zero status transparency, prevent copy-paste errors when ERAS opens, and replace the alumni network "scavenger hunt" with a unified, data-driven school list and review portal.

## Success looks like
- Understand how web applications replace "email + Google Docs" with a real-time, transparent review pipeline (`Drafting` → `Submitted` → `Under Review` → `Feedback Ready` → `Approved`).
- Design relational data models that connect medical students, advisor feedback, ACGME programs, and alumni match history.
- Direct AI to implement features that solve the three core bottlenecks: multi-document drafting/character caps, advisor review queue visibility, and verified alumni-linked school lists.
- Confidently test, evaluate, and navigate a working full-stack prototype running locally.

## Constraints
- Non-technical background: All concepts explained through clinical analogies and medical school domain workflows.
- High efficiency: Short, modular interactive lessons that build storage strength without syntax overwhelm.

## Out of scope
- Manual low-level coding or framework configuration from scratch.
- Non-residency educational software (e.g. pre-med AMCAS, general undergraduate advising).
